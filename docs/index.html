Execution boundary

GitHub hosts the project. Your machine runs the benchmark.

TinyEdgeBench keeps the website static and the measurement path local, so CPU/GPU results reflect the user's installed runtimes, drivers, and actual device.

Why it exists

Fast answers before heavy profiling stacks.

Run locally

The website is a showcase; CLI and Web UI benchmarks execute on the user's own machine.

02

Compare precision modes

Benchmark FP32 baselines against simulated INT8 and shift-only approximations.

03

Export artifacts

Generate summary CSV, Markdown reports, latency plots, and numerical error plots.

04

Compare real backends

Optionally measure PyTorch and ONNX Runtime CPU/CUDA kernels against the NumPy baseline.

Workflow

Configure, run, inspect, export.

YAML mode

python -m tinyedgebench.benchmark --config configs/default.yaml

Interactive wizard

tinyedgebench wizard

Local Web UI

tinyedgebench web

Real backend suite

python -m tinyedgebench.benchmark --config configs/real_backends.yaml

Local GPU suite

python -m tinyedgebench.benchmark --config configs/gpu_backends.example.yaml

Compare saved runs

tinyedgebench compare results/runs/base results/runs/new

Install

Clone it, install it, run it.

TinyEdgeBench is packaged as a Python project with a Streamlit Web UI and pytest coverage for the benchmark core. 

git clone https://github.com/keys2023190905023/TinyEdgeBench.git
cd TinyEdgeBench
python -m pip install -e ".[dev]"
python -m pip install -e ".[real-backends]"
python -m pip install -e ".[real-backends-gpu]"
python -m pytest
tinyedgebench web
